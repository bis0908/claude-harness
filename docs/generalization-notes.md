# 일반화 규칙 (generalization rubric)

이 저장소는 `reviewnavi` (PHP→Next.js 포팅) 프로젝트에서 검증된 에이전트 팀 하네스를, 어느 프로젝트에서든 재사용할 수 있는 **스택 무관 골격**으로 추출한 것이다. 이 문서는 추출 과정에서 적용한 일반화 규칙이며, 골격을 수정·확장할 때도 같은 규칙을 따른다.

## 1. 골격 vs 스택 특화

| 구분 | 위치 | 내용 |
|------|------|------|
| **골격** (스택 무관) | `agents/`, `skills/` | 오케스트레이션·검증·학습·추적 역할. 어느 프로젝트에서든 동작. 전역 설치 대상. |
| **스택 특화** (참조용) | `examples/nextjs-mysql/` | Next.js + MySQL 구현 에이전트·스킬. 복사해 프로젝트에 맞게 변형하는 템플릿. 전역 설치 안 함. |

골격은 "누가 언제 무엇을 검증·조율하는가"를 담고, 구현 자체(코드를 쓰는 일)는 프로젝트별 **구현 에이전트**가 담당한다. 구현 에이전트는 `examples/`를 템플릿으로 삼아 프로젝트에 추가하거나, `harness` 메타 스킬로 생성한다.

## 2. 용어 치환 규칙

| 원본 (reviewnavi 특화) | 일반화 |
|------|--------|
| `reviewnavi`, `reviewnavi_nextjs` | "이 프로젝트" / 삭제 |
| `reviewnavi-*` 스킬명 | 접두사 제거 (`reviewnavi-qa` → `qa`) |
| `page-builder` / `data-layer` / `legacy-reader` (구현 에이전트) | "구현 에이전트" (프로젝트가 정의; 예시는 `examples/nextjs-mysql`) |
| PHP 원본 / 레거시 분석 | "레거시 소스(있을 경우)" / "원본 스펙" |
| JS-only, no-ORM, shadcn 화이트리스트, `__` 테이블 prefix | "프로젝트 CLAUDE.md가 정한 컨벤션" (구체 항목은 프로젝트가 채움) |
| `디자인가이드.html` | "프로젝트 디자인 레퍼런스(있을 경우)" |
| Next.js / mysql2 / Prisma 등 스택명 | 삭제 또는 "데이터 접근 레이어"·"프레임워크" 등 역할명 |

## 3. 외부 경로 의존 — graceful skip / bootstrap (가장 중요)

골격은 아래 경로를 **작업 산출물의 기본 컨벤션**으로 사용한다. 새 프로젝트에는 이 경로가 없으므로, **없으면 깨지지 않고 생성하거나 건너뛴다.**

| 경로 | 용도 | 부재 시 동작 |
|------|------|-------------|
| `_workspace/` | 에이전트 간 중간 산출물 | 첫 사용 시 생성 |
| `docs/progress/milestone-status.md` | 마일스톤 체크리스트 골격 | 로드맵/티켓이 있으면 생성, 없으면 최소 골격 생성 |
| `docs/progress/milestones/M{N}.md` | 마일스톤 작업 로그 | 해당 마일스톤 착수 시 생성 |
| `docs/compound/{카테고리}/` | 재발 방지 학습 누적 | 학습 발생 시 생성 |
| `docs/02-roadmap/*` | 로드맵·작업 티켓 | 있으면 참조, 없으면 "근거 부재"로 명시하고 진행 |

원칙: **경로가 없다는 사실 자체를 결함으로 보고하지 않는다.** 생성하거나, "근거 부재"로 명시하고 진행한다.

## 4. 보존한 것

- 에이전트 역할 경계·입출력 계약·반환 형식 (팀 협업 프로토콜의 핵심)
- 한국어 서술, 문서 구조, 검증 등급(✓/△/✗/⚠) 체계
- `docs/compound/`·`docs/progress/`·`_workspace/` 디렉토리 컨벤션 (하네스 고유 인프라)
- `마일스톤` 용어 (범용 작업 단위로 사용)

## 5. 컨벤션 집행 — 문서 규범 vs install-time 훅 (선택)

골격은 프로젝트 컨벤션을 **문서 규범**(프로젝트 CLAUDE.md·`skills/` 규칙)으로 규정한다. 프로젝트는 여기에 더해, 같은 컨벤션을 **실행 시점에 강제하는 훅**을 선택적으로 둘 수 있다. 프로젝트 `.claude/settings.json` 의 `PreToolUse`/`PostToolUse` 훅으로 금지 파일·시크릿 편집 차단(PreToolUse), 린터 자동검사·금지 명령 차단(PostToolUse) 등을 집행하는 방식이다.

| 집행 수단 | 위치 | 성격 |
|------|------|------|
| 문서 규범 | 프로젝트 CLAUDE.md·`skills/` | 골격이 안내. 에이전트가 읽고 따른다. |
| install-time 훅 (선택) | 프로젝트 `.claude/settings.json` | 프로젝트가 작성. 실행 시점에 차단·검사로 강제. |

원칙: **구체 훅 명령은 스택 특화**(린터·패키지 매니저·금지 확장자·시크릿 파일 패턴)이므로 골격(`agents/`·`skills/`)에 포함하지 않는다. 골격은 "컨벤션을 훅으로도 집행할 수 있다"는 개념만 안내하고, 구체 구현은 프로젝트가 채운다. graceful 기본값: 훅이 없어도 골격 동작에는 영향이 없다.
